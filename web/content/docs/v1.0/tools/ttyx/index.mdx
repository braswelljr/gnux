title: "ttyx"
description: "Print the file name of the terminal connected to standard input."
---

Mirrors GNU `tty`. Run it as `ttyx`, or as `gnux ttyx`.

## Synopsis

```bash
ttyx [OPTION]...
```

## GNU reference

- [GNU coreutils manual: tty invocation](https://www.gnu.org/software/coreutils/manual/html_node/tty-invocation.html)
- [Source: src/tty.c in coreutils/coreutils](https://github.com/coreutils/coreutils/blob/master/src/tty.c)

## Description

`ttyx` prints the file name of the terminal on standard input, such as /dev/pts/3, or 'not a `tty`' when standard input is a pipe, a file or nothing, and then exits with status 1. `-s` prints nothing, so only the exit status tells; GNU deprecates it in favor of '`test -t` 0', which `gnux` has as `testx -t` 0. The name is found without the C library: through /proc on Linux, and on macOS and the BSDs by finding the device in /dev with the same device number, as ttyname(3) does. Windows has no terminal file names, so a console prints as CON (its device name) instead of failing. The exit status is 0 when standard input is a terminal, 1 when it is not, 2 for a command-line mistake and 3 when the name could not be written.

## Permissions

Needs no permissions.

## Use cases

- Making a script behave differently when run by hand than from cron or a pipe.
- Finding which terminal device a session uses, to write to it or check its permissions.
- Refusing to prompt for a password when there is no terminal to type it on.
- Logging which terminal a command was run from.
- Checking that a CI job really has no terminal attached.

## Flags

```text
      --help      display this help and exit
      --quiet     same as --silent
  -s, --silent    print nothing, only return an exit status
      --version   output version information and exit
```

## Examples

### See which terminal device your shell is using

```bash tab="bash" tab-group="shell"
ttyx
```

```powershell tab="PowerShell" tab-group="shell"
ttyx
```

```text title="Output"
/dev/pts/3
```

### See what a command reading from a pipe gets

```bash tab="bash" tab-group="shell"
echox | ttyx
```

```powershell tab="PowerShell" tab-group="shell"
echox | ttyx
```

```text title="Output"
not a tty
```

### Only prompt for confirmation when someone is at the keyboard

```bash tab="bash" tab-group="shell"
if ttyx -s; then read -p 'Deploy to production? ' ok; else ok=yes; fi
```

```powershell tab="PowerShell" tab-group="shell"
if (ttyx -s; $LASTEXITCODE -eq 0) { $ok = Read-Host 'Deploy to production?' } else { $ok = 'yes' }
```

### Refuse to ask for a password in a cron job or CI run

```bash tab="bash" tab-group="shell"
ttyx -s || { echox 'no terminal: set DB_PASSWORD instead' >&2; exit 1; }
```

```powershell tab="PowerShell" tab-group="shell"
ttyx -s; if ($LASTEXITCODE -ne 0) { Write-Error 'no terminal: set DB_PASSWORD instead'; exit 1 }
```

### Record the terminal in an audit log next to the user and time

```bash tab="bash" tab-group="shell"
echox "$(datex -Iseconds) $(whoamix) $(ttyx)" >> audit.log
```

```powershell tab="PowerShell" tab-group="shell"
"$(datex -Iseconds) $(whoamix) $(ttyx)" >> audit.log
```

### Check who may write to your terminal (as mesg would)

```bash tab="bash" tab-group="shell"
lsx -l "$(ttyx)"
```

```powershell tab="PowerShell" tab-group="shell"
ttyx
```

### Show progress only when a person is watching

```bash tab="bash" tab-group="shell"
ttyx -s && echox 'Copying 4.2 GB, this takes a few minutes...'
```

```powershell tab="PowerShell" tab-group="shell"
ttyx -s; if ($LASTEXITCODE -eq 0) { 'Copying 4.2 GB, this takes a few minutes...' }
```

### Confirm a CI job has no terminal attached

```bash tab="bash" tab-group="shell"
ttyx || echox 'running unattended'
```

```powershell tab="PowerShell" tab-group="shell"
ttyx; if ($LASTEXITCODE -ne 0) { 'running unattended' }
```

```text title="Output"
not a tty
running unattended
```

### Get the exit status alone, for a test in a script

```bash tab="bash" tab-group="shell"
ttyx -s; echox $?
```

```powershell tab="PowerShell" tab-group="shell"
ttyx -s; $LASTEXITCODE
```

```text title="Output"
0
```

### Compare with the portable equivalent GNU recommends

```bash tab="bash" tab-group="shell"
testx -t 0 && echox interactive
```

```powershell tab="PowerShell" tab-group="shell"
testx -t 0; if ($LASTEXITCODE -eq 0) { 'interactive' }
```

### Check for a terminal in the portable gnux shell

```bash tab="bash" tab-group="shell"
gnux shell -c 'ttyx -s && echox interactive || echox batch'
```

```powershell tab="PowerShell" tab-group="shell"
gnux shell -c 'ttyx -s && echox interactive || echox batch'
```

## Options

Each option has a page of its own, with its usage and examples.

- [--quiet](/docs/v1.0/tools/ttyx/quiet): Same as `--silent`.
- [-s, --silent](/docs/v1.0/tools/ttyx/silent): Print nothing, only return an exit status.

## Exit status

| Status | Meaning |
|--------|---------|
| 0 | standard input is a terminal |
| 1 | standard input is not a terminal |
| 2 | a command-line mistake |
| 3 | a write error |

## Help in the terminal

```bash
ttyx --help                # options, first examples, exit status
gnux help ttyx             # this page: the full manual
gnux help ttyx --OPTION    # one option in depth, with its examples
```
