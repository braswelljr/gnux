Mirrors GNU `test`. Run it as `testx`, or as `gnux testx`.

## Synopsis

```bash
testx EXPRESSION
```

## GNU reference

- [GNU coreutils manual: test invocation](https://www.gnu.org/software/coreutils/manual/html_node/test-invocation.html)
- [Source: src/test.c in coreutils/coreutils](https://github.com/coreutils/coreutils/blob/master/src/test.c)

## Description

`testx` evaluates EXPRESSION and exits with status 0 when it is true and 1 when it is false; it prints nothing. With no EXPRESSION it is false. Strings: `-n` STRING (not empty), `-z` STRING (empty), STRING alone (not empty), S1 = S2 (also ==), S1 != S2, and S1 \< S2 or S1 > S2, comparing bytes (the C locale). Integers: N1 `-eq`, `-ne`, `-lt`, `-le`, `-gt` or `-ge` N2, where an integer is an optional sign and decimal digits of any length, with surrounding blanks allowed. Files: `-e` (exists), `-f` (regular file), `-d` (directory), `-h` or `-L` (symbolic `link`, not followed), `-b` and `-c` (block and character devices), `-p` (named pipe), `-S` (socket), `-s` (size above zero), `-r`, `-w` and `-x` (readable, writable, executable by you), `-u`, `-g` and `-k` (set-user-ID, set-group-ID and sticky bits), `-O` and `-G` (owned by your effective user or group), `-t` FD (descriptor FD is a terminal), and F1 `-nt`, `-ot` or `-ef` F2 (newer, older, or the same file). Expressions combine with ! (not), `-a` (and, binding tighter), `-o` (or) and parentheses, which must be separate arguments (quote them from the shell). As POSIX requires, one to four arguments are read by their count first, so `testx -n` = `-n` compares two strings. A malformed expression is diagnosed with GNU's wording ('a': unary operator expected, invalid integer 'x', missing argument after '`-f`', extra argument 'c') and exits with status 2. Differences from GNU `test`: the [ form is not provided (a `gnux` tool's name is its GNU name with an x appended), a lone `--help` or `--version` prints help or the version where GNU `test` would treat it as a non-empty string, the `-l` STRING length operand is not implemented, and off Unix `-O` and `-G` are always false while `-r`, `-w` and `-x` are read from the permission bits.

## Permissions

Reads file metadata only: `-e`, `-f`, `-d` and the other file tests need search permission on the directories leading to the file; `-r`, `-w` and `-x` ask the operating system whether you could read, write or execute it, without trying. Nothing is ever modified.

## Use cases

- Checking that a file or directory exists before using it in a script.
- Branching on whether a variable is empty with `-z` or `-n`.
- Comparing version numbers or counts with `-lt`, `-ge` and the other integer tests.
- Rebuilding only when a source file is newer than its output with `-nt`.
- Checking that a script is writing to a terminal with `-t` 1 before using colors.
- Guarding a destructive step with && in the portable `gnux shell`.
- Verifying permissions (`-r`, `-w`, `-x`) before a deployment step runs.

## Flags

```text
      --help      display this help and exit
      --version   output version information and exit
```

## Examples

### Check that a file exists

```bash tab="bash" tab-group="shell"
testx -e config.json && echox found
```

```powershell tab="PowerShell" tab-group="shell"
testx -e config.json; if ($LASTEXITCODE -eq 0) { 'found' }
```

### Check for a directory

```bash tab="bash" tab-group="shell"
testx -d build || mkdirx build
```

```powershell tab="PowerShell" tab-group="shell"
testx -d build; if ($LASTEXITCODE -ne 0) { mkdirx build }
```

### Check that a variable is not empty

```bash tab="bash" tab-group="shell"
testx -n "$NAME" && echox "hello, $NAME"
```

```powershell tab="PowerShell" tab-group="shell"
testx -n "$env:NAME"; if ($LASTEXITCODE -eq 0) { "hello, $env:NAME" }
```

### Compare two strings

```bash tab="bash" tab-group="shell"
testx "$BRANCH" = main && echox "on main"
```

```powershell tab="PowerShell" tab-group="shell"
testx "$env:BRANCH" = main; if ($LASTEXITCODE -eq 0) { 'on main' }
```

### Compare two numbers

```bash tab="bash" tab-group="shell"
testx 10 -gt 9 && echox bigger
```

```powershell tab="PowerShell" tab-group="shell"
testx 10 -gt 9; if ($LASTEXITCODE -eq 0) { 'bigger' }
```

### Rebuild only when the source is newer than the output

```bash tab="bash" tab-group="shell"
testx main.go -nt app && go build -o app .
```

```powershell tab="PowerShell" tab-group="shell"
testx main.go -nt app; if ($LASTEXITCODE -eq 0) { go build -o app . }
```

### Combine conditions with -a and -o

```bash tab="bash" tab-group="shell"
testx -f go.mod -a -d .git && echox 'a Go repository'
```

```powershell tab="PowerShell" tab-group="shell"
testx -f go.mod -a -d .git; if ($LASTEXITCODE -eq 0) { 'a Go repository' }
```

### Negate and group (parentheses are separate, quoted arguments)

```bash tab="bash" tab-group="shell"
testx ! '(' -e a.lock -o -e b.lock ')' && echox unlocked
```

```powershell tab="PowerShell" tab-group="shell"
testx '!' '(' -e a.lock -o -e b.lock ')'; if ($LASTEXITCODE -eq 0) { 'unlocked' }
```

### Check that a file is not empty

```bash tab="bash" tab-group="shell"
testx -s report.csv || echox 'report is empty'
```

```powershell tab="PowerShell" tab-group="shell"
testx -s report.csv; if ($LASTEXITCODE -ne 0) { 'report is empty' }
```

### Check whether standard output is a terminal

```bash tab="bash" tab-group="shell"
testx -t 1 && echox interactive
```

```powershell tab="PowerShell" tab-group="shell"
testx -t 1; if ($LASTEXITCODE -eq 0) { 'interactive' }
```

### See the status of a malformed expression (2)

```bash tab="bash" tab-group="shell"
testx 1 -eq one; echox "exit status $?"
```

```powershell tab="PowerShell" tab-group="shell"
testx 1 -eq one; "exit status $LASTEXITCODE"
```

### Guard a step in the portable gnux shell

```bash tab="bash" tab-group="shell"
gnux shell -c 'testx -d dist && rmx -r dist'
```

```powershell tab="PowerShell" tab-group="shell"
gnux shell -c 'testx -d dist && rmx -r dist'
```

## Exit status

| Status | Meaning |
|--------|---------|
| 0 | EXPRESSION is true |
| 1 | EXPRESSION is false, or missing |
| 2 | EXPRESSION is malformed (diagnosed on standard error) |

## Help in the terminal

```bash
testx --help                # options, first examples, exit status
gnux help testx             # this page: the full manual
gnux help testx --OPTION    # one option in depth, with its examples
```
