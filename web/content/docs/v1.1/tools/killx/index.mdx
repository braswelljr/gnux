Mirrors GNU `kill`. Run it as `killx`, or as `gnux killx`.

## Synopsis

```bash
killx [-s SIGNAL | -SIGNAL] PID...
```

## GNU reference

- [GNU coreutils manual: kill invocation](https://www.gnu.org/software/coreutils/manual/html_node/kill-invocation.html)
- [Source: src/kill.c in coreutils/coreutils](https://github.com/coreutils/coreutils/blob/master/src/kill.c)

## Description

`killx` sends a signal, TERM by default, to each process PID. The signal is given as `-s` SIGNAL, `-n` NUMBER, or `-SIGNAL` directly (-9, `-KILL`, `-SIGKILL`), by name in any case with or without the SIG prefix, or by number; signal 0 sends nothing and only checks that the process exists. A PID that cannot be signaled is reported and the remaining PIDs are still tried. `-l` prints the signal names, or converts each operand between a name and a number (an exit status above 128 is taken as 128 plus a signal, so '`killx -l` 137' prints KILL); `-L` (or `-t`) prints a table of numbers, names and descriptions. Unlike GNU `kill`, `killx` reads options wherever they appear before '--', so '`killx` 1234 -9' sends KILL to 1234 rather than signaling process group 9; a negative PID (a process group, or -1 for every process) must follow '--'. Giving two signals is an error. On Windows, which has no signals, only KILL and TERM can be sent, both by terminating the process, and 0 checks that it exists; any other signal fails with 'Operation not supported'.

## Permissions

A process may be signaled by its owner, or by root (or with CAP_KILL). On Windows, terminating a process needs the right to terminate it, which an administrator has for every process.

## Use cases

- Stopping a runaway or hung process.
- Asking a daemon to reload its configuration with HUP.
- Checking whether a process is still alive with signal 0.
- Translating a shell exit status such as 137 into a signal name.
- Stopping a process the same way on Linux, macOS and Windows.

## Flags

```text
      --help            display this help and exit
  -l, --list            list signal names, or convert signal names to/from numbers
  -n, --number NUMBER   same as -s, with a NUMBER
  -s, --signal string   specify the name or number of the signal to be sent
  -L, --table           print a table of signal information (also -t)
      --version         output version information and exit
```

## Examples

### Ask a process to terminate

```bash tab="bash" tab-group="shell"
killx 1234
```

```powershell tab="PowerShell" tab-group="shell"
killx 1234
```

### Kill a process that ignores TERM

```bash tab="bash" tab-group="shell"
killx -9 1234
```

```powershell tab="PowerShell" tab-group="shell"
killx -9 1234
```

### Name the signal

```bash tab="bash" tab-group="shell"
killx -s KILL 1234
```

```powershell tab="PowerShell" tab-group="shell"
killx -s KILL 1234
```

### Ask a daemon to reload its configuration

```bash tab="bash" tab-group="shell"
killx -HUP "$(catx /run/nginx.pid)"
```

```powershell tab="PowerShell" tab-group="shell"
killx -HUP (catx nginx.pid)
```

### Check whether a process is alive

```bash tab="bash" tab-group="shell"
killx -0 1234 && echox alive
```

```powershell tab="PowerShell" tab-group="shell"
killx -0 1234; if ($LASTEXITCODE -eq 0) { 'alive' }
```

### Signal several processes

```bash tab="bash" tab-group="shell"
killx -TERM 1234 5678
```

```powershell tab="PowerShell" tab-group="shell"
killx -TERM 1234 5678
```

### Signal a process group

```bash tab="bash" tab-group="shell"
killx -TERM -- -1234
```

```powershell tab="PowerShell" tab-group="shell"
killx -TERM -- -1234
```

### List the signal names

```bash tab="bash" tab-group="shell"
killx -l
```

```powershell tab="PowerShell" tab-group="shell"
killx -l
```

### Show the table of signals

```bash tab="bash" tab-group="shell"
killx -L
```

```powershell tab="PowerShell" tab-group="shell"
killx -L
```

### Find which signal ended a command that exited with 137

```bash tab="bash" tab-group="shell"
killx -l 137
```

```powershell tab="PowerShell" tab-group="shell"
killx -l 137
```

### Convert a signal name to its number

```bash tab="bash" tab-group="shell"
killx -l TERM
```

```powershell tab="PowerShell" tab-group="shell"
killx -l TERM
```

### Send a signal in the portable gnux shell

```bash tab="bash" tab-group="shell"
gnux shell -c 'killx -0 1234 || echox gone'
```

```powershell tab="PowerShell" tab-group="shell"
gnux shell -c 'killx -0 1234 || echox gone'
```

## Options

Each option has a page of its own, with its usage and examples.

- [-l, --list](/docs/v1.1/tools/killx/list): List signal names, or convert signal names to/from numbers.
- [-n, --number](/docs/v1.1/tools/killx/number): Same as `-s`, with a NUMBER.
- [-s, --signal](/docs/v1.1/tools/killx/signal): Specify the name or number of the signal to be sent.
- [-L, --table](/docs/v1.1/tools/killx/table): Print a table of signal information (also `-t`).

## Exit status

| Status | Meaning |
|--------|---------|
| 0 | success: every operand was processed |
| 1 | failure: an operand could not be processed (diagnosed on standard error), or a command-line mistake |

## Help in the terminal

```bash
killx --help                # options, first examples, exit status
gnux help killx             # this page: the full manual
gnux help killx --OPTION    # one option in depth, with its examples
```
