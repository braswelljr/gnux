## [Unreleased]

### Added

- gnux on npm: `npm install --save-dev gnux` puts every tool on the PATH of a project's package
  scripts, under its gnux name (`rmx`, never `rm`), so one dependency replaces rimraf, mkdirp,
  cpy-cli, shx and cross-env on every platform. The native binary comes in a package per
  platform (`gnux-linux-x64`, `gnux-darwin-arm64`, `gnux-win32-x64`, ...) that npm installs as
  an optional dependency, with no install script; `require('gnux')` offers `run` and
  `binaryPath`, and `GNUX_BINARY` points the launchers at another gnux. The Release workflow
  publishes them with provenance when `NPM_TOKEN` is set; `make npm/pack` builds them locally.
  The Node and npm guide covers package scripts, globs on Windows and the JavaScript API.
- Documentation for each release on the website: a version select in the docs sidebar switches
  between the latest docs and those of every stable release as it shipped (`/docs/v1.0/...`),
  staying on the same page when that version has it. Older versions say so at the top of each
  page and are left out of search, the sitemap and `llms.txt`. The Release workflow snapshots
  each stable release's docs with `tools/docsnap` (`make docs/snapshot TAG=vX.Y.Z`).
- gnux builds for WASI (`GOOS=wasip1`, `make wasi`): the tools that only read and write files
  run under a WASI runtime, which lets them reach only the directories it opens.
- `gnux shell --sandbox DIR [--sandbox-read DIR]`: the script, and every program it starts, can
  read and write DIR, read the system's directories, and reach nothing else, enforced by the
  kernel: Landlock on Linux, Seatbelt on macOS, an AppContainer on Windows and Capsicum on
  FreeBSD. Where no sandbox can be used it refuses with status 125 rather than run unconfined.
- For Go callers: `core/fsys`, through which every engine now reaches the file system. By
  default it is the os package; `fsys.Use(fsys.NewRooted(...))` confines every engine to a set
  of directories through `os.Root`, in any program.
- `gnux mcp DIR...`: a Model Context Protocol server inside that sandbox, so that an AI agent
  (Claude Code, Claude Desktop, Cursor, VS Code) can run gnux command lines in a project and
  reach nothing outside it, each call with a time limit and an output limit. The Sandbox and AI
  agents guide covers both.

### Fixed

- `lsx -l` with files and directories as operands sizes the files' columns to fit the directories too, as GNU does: `ls -l a.txt dir` padded the size column to the file alone.

## [1.1.0] - 2026-10-19

gnux 1.1.0 adds nine tools and closes most of the gap with GNU's option surface: backups in
`cpx`, `mvx`, `lnx` and `installx`, every GNU ls option but `-f` and `-Z` (GNU's ten quoting
styles, `--zero`, `--hyperlink`, `--dired`, `--block-size`, ...), GNU's getopt rules for every
option, and the options
`chgrpx --from`, `chmodx -h`, `datex --resolution`, `cpx --remove-destination`, `mvx --no-copy`,
`tailx --max-unchanged-stats` and `sortx -R`. Every one of them is now checked against GNU
coreutils itself by a conformance harness that runs in CI.

### Added

- Four more coreutils tools. `archx` prints the machine architecture, as `unamex -m` does.
  `factorx` prints the prime factors of each number, with no size limit, and `-h`
  (`--exponents`) writes repeated factors as `p^e`. `sumx` prints the BSD checksum (or, with
  `-s`, the System V one) and block count of each file. `tsortx` sorts pairs of strings
  topologically, in GNU's order, and names the strings of any loop it finds.
- For Go callers: `cksum.BSD` and `cksum.SysV`, the two legacy checksums on any `io.Reader`, and
  `uname.System`, the system information `unamex` prints.
- Five more coreutils tools. `dirx` and `vdirx` are `lsx` with GNU `dir` and `vdir`'s defaults:
  columns or the long format whatever the output is, and names with unprintable characters
  escaped. `groupsx` prints the groups of the process or of each user named. `usersx` prints
  the users logged in. `lognamex` prints the name the user logged in as, which stays the same
  under `su` and `sudo`.
- `[ EXPRESSION ]`: the test tool answers to `[`, with the closing `]` required, as
  `gnux [ ... ]` and as a link named `[`, as it already did in `gnux shell`.
- `testx -l STRING`: the length of STRING, for either side of an integer comparison, as in GNU
  test.
- For Go callers: `id.Self`, `id.LookupUser`, `id.GroupName` and `id.GroupList`, and
  `ls.NewAs`, an ls engine whose diagnostics carry another name.
- Docker images on GHCR with every release: `ghcr.io/braswelljr/gnux` (Alpine) and the same
  tags with `-scratch` appended, gnux and its links alone in a `FROM scratch` image, for
  linux/amd64 and linux/arm64.
- Every release archive has an SPDX SBOM beside it, and `checksums.txt` is signed with cosign
  (keyless, `checksums.txt.sigstore.json`).
- `core.Diag.ChildErr`, the error stream for a child process that runs while diagnostics may
  still be written.

- Long options may be abbreviated to any unambiguous prefix in every tool (`rmx --rec`), as GNU's
  getopt allows; an ambiguous one lists its possibilities.
- A GNU conformance harness: `make conformance` (or `make conformance/docker`) runs each case
  in `cmd/testdata/conformance/` through the GNU tools and through gnux and compares output,
  errors and exit status; CI runs it on every change.
- Fuzz targets for the parsers of `printfx`, `seqx`, `trx` and `cutx`.
- GNU options that were missing: `chgrpx --from=CURRENT_OWNER:CURRENT_GROUP`; `chmodx -h`
  (`--no-dereference`) and `--dereference`, from GNU chmod 9.6 (a link that is not followed has
  its own mode changed where links have one, and is reported as unchanged on Linux);
  `datex --resolution`, and `%-N` printing as many digits as the clock's resolution needs;
  `cpx --remove-destination`; `mvx --no-copy`; `tailx --max-unchanged-stats` (validated; tailx
  already checks a followed name on every poll); and `sortx -R` (`--random-sort`,
  `--sort=random`) with `--random-source=FILE`, which orders exactly as GNU sort does for the
  same FILE. Each has GNU conformance cases in `cmd/testdata/conformance/gnu-options.txt`.
- Backups in `cpx`, `mvx`, `lnx` and `installx`: `--backup[=CONTROL]` (`none`, `simple`,
  `existing`, `numbered` and their synonyms), `-b`, and `-S`/`--suffix`, with `VERSION_CONTROL`
  and `SIMPLE_BACKUP_SUFFIX`, as in GNU: the same backup names, `-v` lines and refusals,
  checked against GNU in `cmd/testdata/conformance/backups.txt`. For Go callers,
  `core.Backup` makes and names backups, and `core.ParseBackupControl` reads a CONTROL word.
- The rest of GNU ls's options in `lsx`, `dirx` and `vdirx`: `--quoting-style` with all ten of
  gnulib's styles, `-N` (`--literal`) and the `QUOTING_STYLE` variable, `--show-control-chars`,
  `--format`, `--indicator-style`, `--zero`, `--block-size` with `LS_BLOCK_SIZE` and
  `BLOCK_SIZE`, `-k` (`--kibibytes`), `--author`, `--hyperlink` and `-D` (`--dired`), each
  settled by option order as GNU does and checked against GNU in
  `cmd/testdata/conformance/ls-options.txt`.

### Changed

- `lsx` on a terminal quotes names for the shell, as GNU ls has since 8.25: `'a b'`,
  `'new'$'\n''line'`, with unquoted names moved a column right to line up with quoted ones. Use
  `-N` (or `QUOTING_STYLE=literal`) for the old output. For Go callers, `ls.Quoting`'s zero value
  is now `ls.QuoteAuto`, GNU's default, and `ls.QuoteLiteral` is `-N`.
- Option errors are worded as GNU's getopt words them in every tool: `unrecognized option
  '--foo'`, `invalid option -- 'z'`, `option requires an argument -- 'n'`, `option '--force'
  doesn't allow an argument`.
- `findx` reports a mistake in its expression without the `Try 'findx --help'` line, as GNU find
  does; the status is still 1.
- `chmodx -P` answers to `--physical` instead of `--no-dereference`, which is GNU's long name
  for `-h` and now means that.
- `mktempx -p` answers to `--base-dir` instead of `--dir`, which is GNU's abbreviation of
  `--directory` and now means that.
- On the website, a tool without options is a single page in the sidebar rather than a folder
  with nothing to open; its address, `/docs/tools/<tool>`, is unchanged.
- Building gnux needs Go 1.26, which `go.mod` has required since `golang.org/x/crypto` 0.57;
  the Dockerfile and the documented requirements say so now.

### Fixed

- `nicex` no longer races with the command it runs over a shared error stream that is not a
  file (a `gnux shell` pipeline, the playground, an embedding program): its warning and the
  command's own error output used to be written from two goroutines at once.
- `sortx -g` reads hexadecimal numbers as `strtold` does (`0x10` is 16).
- `wcx` keeps its column width when an operand cannot be read, as GNU 9 does.
- `rmx .` without `-r` reports `Is a directory`, and `rmx -d .` tries and fails, as in GNU;
  only `-r` refuses `.` and `..` by name.
- `grepx '['` reports `Invalid regular expression`, as GNU grep 3.11 does.
- `chownx -R --dereference` and `chgrpx -R --dereference` without `-H` or `-L` no longer add a
  `Try '... --help'` line to the error, as GNU does not.
- `chmodx -v` reports `'FILE' could not be accessed` for a file it cannot reach, as GNU does.
- `lsx`: an invalid word for an option (`--sort=x`, `--color=x`, `--time=x`) exits 1, as GNU
  does, not 2; the error lists synonyms on one line (`'always', 'yes', 'force'`) and `--sort`'s
  words in GNU's order. A diagnostic quotes a name as GNU's does.
- `statx -c %N` quotes every name, and a link's target, as GNU does (`'a.txt'`, `"it's"`,
  `''$'\001'`), in the style `QUOTING_STYLE` names; the default format names files as they are
  (`File: a b`), where it used to quote them.
- `lnx` names a directory it refuses as GNU does, quoted only when the name needs it
  (`lnx: e: cannot overwrite directory`).
- The Docker image builds again: it used Go 1.25, older than `go.mod` requires.

## [1.0.0] - 2026-10-14

gnux 1.0.0 is the first stable release. From here on the command-line interface of every tool
and of `gnux shell`, the shell's language, and the Go packages under `core/` follow Semantic
Versioning: a change that breaks them waits for 2.0.

The headline is `gnux shell`, which can now run a real script: it branches, loops, takes
arguments and reads the output of a command, the same way on Linux, macOS and Windows.

### Added

- Control flow in `gnux shell`: `if` / `elif` / `else` / `fi`, `for NAME in WORD...; do ...;
  done` (over the script's arguments when `in` is left out), `while ...; do ...; done` and
  `case WORD in PATTERN | PATTERN) ... ;; esac`, on one line or over several, with `break [N]`
  and `continue [N]`. A whole construct can be redirected or piped.
- Command substitution, `$(command)`. Unquoted, its output becomes one word per line, never one
  per space, so file names with spaces survive `for f in $(findx ...)`; quoted, it is a single
  word. It runs as a subshell: variables it sets and a `cd` it makes end with it.
- Script arguments: `gnux shell SCRIPT ARG...` and `gnux shell -c STRING NAME ARG...` reach the
  script as `$1`, `$2`, ..., `$#`, `$0`, `"$@"` and `$*`, with the builtins `shift [N]` and
  `set -- ARG...`.
- `gnux shell -u`, and `set -u` inside a script: expanding a variable that was never set stops
  the script with `gnux: NAME: unbound variable` and status 1. `${NAME:-default}` reads one that
  may be missing.
- `! command` inverts an exit status, `[ EXPRESSION ]` runs the `test` tool, and `set -e` /
  `set +e` turn `-e` on and off from inside a script.
- An interactive session continues an unfinished `if`, loop or `case` on the next line, at the
  prompt `> `.
- For Go callers of `core/shell`: `Options.NoUnset`, `Shell.SetArgs`, `Shell.LoopLimit`,
  `ContinuePrompt` and `Incomplete`.
- On the website's home page, taking the keyboard now runs what is typed: Enter hands the line
  to the real gnux, loaded in the browser as the playground loads it, and the up and down
  arrows bring back earlier lines. Nothing is downloaded until the keyboard is taken. Once it
  is, the drawn keys can be clicked as well, with shift and caps lock held by the board.
- The playground offers loops and conditions among its examples, and stops a loop that would
  never end after 10,000 turns instead of freezing the tab.

### Changed

- `gnux shell SCRIPT EXTRA` and `gnux shell -c STRING EXTRA` are no longer usage errors: the
  extra operands are the script's arguments. Options are read only before `SCRIPT`.
- `(` and `)` are syntax in `gnux shell`. Quote them where a tool expects them:
  `findx . '(' -name a -o -name b ')'`.
- `$1` to `$9`, `$#`, `$@`, `$*` and `$0` are expanded in `gnux shell`; they used to be literal
  text. Write `\$1` or use single quotes for the characters themselves.
- With `gnux shell -e`, the condition of an `if` or a `while` and a command after `!` may fail
  without stopping the script, as in sh.
- In `gnux shell`, the value of an assignment is never globbed (`X=*` stores `*`), a leading `~`
  in it is the home directory (`X=~/bin`), and `A=1 B=$A` on one line gives `B` the new `A`.
- The shell's own diagnostics about a command (`command not found`, a redirection that cannot
  be opened) go to that command's standard error, so `2>` captures them.
- The keyboard on the website's home page is the visitor's own: an M5 MacBook Pro's on an Apple
  device (icons over the F names, symbols on tab, caps lock, shift, delete and return, the
  globe on fn, each modifier's symbol over its name) and the latest Microsoft Surface Laptop's,
  with the Copilot key, anywhere else.
- The home page's monitor and keyboard are sized to fit the viewport together, and every
  animated terminal on the site fills from the top down, as a real one does.

## [0.0.2] - 2026-10-13

gnux grows from 22 tools to 85: nearly all of coreutils, plus `grepx`, `sedx`, `findx` and
`xargsx` for the scripts that need more than coreutils. Releases now cover nine platforms and
reach Homebrew, Scoop, winget, the Snap Store, the AUR and `.deb` / `.rpm` / `.apk` packages.

### Added

- 59 more coreutils tools:
  - text: `sortx`, `uniqx`, `cutx`, `trx`, `teex`, `seqx`, `printfx`, `pastex`, `joinx`,
    `commx`, `nlx`, `foldx`, `fmtx`, `expandx`, `unexpandx`, `tacx`, `splitx`, `csplitx`,
    `shufx`, `odx`;
  - checksums and encoding: `md5sumx`, `sha1sumx`, `sha224sumx`, `sha256sumx`, `sha384sumx`,
    `sha512sumx`, `b2sumx`, `cksumx`, `base32x`, `base64x`;
  - file attributes: `chmodx`, `chownx`, `chgrpx`, `statx`, `dux`, `dfx`, `mktempx`, `installx`,
    `truncatex`, `readlinkx`, `linkx`, `unlinkx`;
  - system: `datex`, `unamex`, `whoamix`, `idx`, `hostnamex`, `nprocx`, `printenvx`, `ttyx`,
    `whox`, `uptimex`, `timeoutx`, `nicex`, `nohupx`, `killx`, `testx`, `exprx`, `ddx`.
- Four tools from beyond coreutils, the ones a build or CI script reaches for next: `grepx`
  (GNU grep), `sedx` (GNU sed), and `findx` and `xargsx` (GNU findutils). Each mirrors its GNU
  counterpart's options, diagnostics and exit statuses, and lists what it does not implement on
  its reference page.
  - `grepx`: basic, extended and fixed-string patterns, context lines, recursive search with
    `--include` / `--exclude` / `--exclude-dir`, counts, file lists, `-o`, colors.
  - `sedx`: the whole script language (addresses, `s` with its flags and case conversions,
    hold space, branches, `a` / `i` / `c`, `r` / `w`) and in-place editing with `-i[SUFFIX]`.
  - `findx`: the expression language with its operators, the name, type, size, time,
    permission and owner tests, `-printf`, `-delete`, `-prune`, and `-exec` / `-execdir` /
    `-ok`.
  - `xargsx`: quoting, `-0`, `-d`, `-n`, `-L`, `-I`, `-P`, `-p`, `-t`, `-r`, and GNU's exit
    statuses 123 to 127.
  - Patterns in `grepx`, `sedx` and `findx -regex` are matched by Go's RE2 engine, which runs
    in linear time but has no back references: a pattern that uses one (`\(a\)\1`) is refused
    with a message instead of being matched differently. `sedx` refuses its `e` command, and
    `grepx` refuses `-P`.
- `xargsx` and `findx -exec` run a command named after a gnux tool in-process, so
  `findx . -name '*.map' | xargsx rm` works on a machine with no GNU tools installed, Windows
  included, and inside `gnux shell`. Any other command is a program found on `PATH`.
- Where GNU has a known rough edge, the new tools fix it and document it: `dux` reads
  directories in parallel and lists them in a stable order; recursive `chmodx`, `chownx` and
  `chgrpx` refuse `/` by default; `nicex` maps niceness onto Windows priority classes and
  `nohupx` detaches from the console on Windows, so both work there; `killx 1234 -9` never
  signals process group 9; `dfx`, `whox`, `uptimex` and `statx` report the same fields on Linux,
  macOS, FreeBSD and Windows without cgo.
- Releases built by GoReleaser (`.goreleaser.yaml`), for four more platforms (`linux/riscv64`,
  `freebsd/amd64`, `freebsd/arm64`, `windows/arm64`), with shell completions in every archive
  and a build provenance attestation. Archive names are unchanged.
- Package managers, published with each release: a Homebrew cask and
  a Scoop manifest, both served from this repository (`Casks/`, `bucket/`), winget manifests, a snap
  (`snap install gnux`), an AUR package (`gnux-bin`), and `.deb`, `.rpm` and `.apk` packages
  attached to the release for Debian, Ubuntu, Fedora, RHEL, openSUSE and Alpine.
- setup-gnux, a GitHub Action (`uses: braswelljr/gnux@v0`) that installs a checksum-verified
  release on Linux, macOS and Windows runners and puts every tool on `PATH`.
- `gnux completion bash|zsh|fish|powershell`, listed in `gnux --help`.
- Documentation examples can show their output (`docmeta.Example.Output`), rendered under the
  commands in every reference page.
- Website: an install page with copyable steps per platform (macOS, Windows, Linux and FreeBSD,
  Go, GitHub Actions, Docker); a pausable marquee of every tool; a "why gnux" strip; and, on
  every tool page, a GNU reference and examples with bash and PowerShell tabs that remember your
  choice.
- Library: `core.FlushOutput`, which reports a failed final write (`write error: No space left
  on device`) instead of exiting 0; `core.NewReader`, `core.NewWriter` and `core.BufferSize`,
  the buffering every tool shares; `core.Trap`, which carries a panic on a tool's own goroutine
  back to its caller; and `shell.Shell.Glob`, the injection point for globbing.
- A benchmark suite over the real tools: `make bench` reports throughput and allocations for
  each tool on generated text, a directory tree and shell pipelines; `make bench/save` and
  `make bench/compare` compare two runs, and `make bench/check` fails when a benchmark got
  slower or allocates more, which the new Bench workflow runs on every pull request against
  its base commit.
- Fuzz tests for every parser (the shell, `sedx` scripts, `grepx` patterns, `findx`
  expressions, `xargsx` input), run in CI and with `make fuzz`.

### Changed

- `gnux TOOL` starts as fast as the tool does under its own name: a first argument that names a
  tool runs it directly, without building the root command and every other tool's flags first.
  `gnux shell` no longer builds every tool's command before reading a script, nor rebuilds the
  tool list for each command it runs.
- A filter answers each line as it gets it: `catx -n` and `headx`, like the new `nlx`, `cutx`,
  `trx`, `foldx`, `expandx`, `unexpandx`, `pastex`, `uniqx`, `grepx` and `sedx`, pass their
  output on whenever their input has run dry, instead of holding it until a buffer fills.
  Behind `tail -f`, a build log or a terminal they no longer look hung; on bulk input nothing
  changes.
- A tool that panics is reported as `TOOL: internal error` with status 2 instead of ending the
  process, so one tool's bug does not take a shell pipeline, the playground or an embedding
  program down with it. That holds for a panic on a goroutine the tool started too (`rmx`
  workers, `dux`, `xargsx -P`, a pipeline stage).
- Running a tool with tens of thousands of arguments, as `xargsx` and `findx -exec` do, no
  longer scans them several times before the tool starts: about 20 times less memory for such
  a call, and a third less work for every call.
- Every tool reads and writes through 64 KiB buffers where it used 4 KiB ones; `catx -n` is
  about twice as fast on large inputs, with the same output.
- Release tags must be full versions (`v1.2.3`, `v1.2.3-rc.1`); each stable release moves its
  major tag (`v0`), which the GitHub Action is used by.
- Dependabot also updates the website's pnpm packages.

## [0.0.1] - 2026-10-11

### Added

- 22 GNU-compatible tools in one multi-call binary, `gnux`: `basenamex`, `catx`, `cpx`, `dirnamex`, `echox`, `envx`, `falsex`, `headx`, `lnx`, `lsx`, `mkdirx`, `mvx`, `pwdx`, `realpathx`, `rmx`, `rmdirx`, `sleepx`, `tailx`, `touchx`, `truex`, `wcx` and `yesx`. Each runs as its own name, as its GNU name through a link, or as `gnux <tool>`, with GNU's flags, diagnostics and exit statuses.
- `gnux shell`, a small portable POSIX sh subset whose commands are the tools, run in-process, so one script behaves the same on Linux, macOS and Windows.
- Every tool's engine as an importable Go package under `core/`, plus `cmd.RunTool` and `cmd.NewShell` for running tools and scripts from Go.
- `gnux help TOOL [OPTION]` for a tool's full manual, or one option in depth.
- The reference in markdown, man, YAML and reStructuredText under `documentation/`, generated from the code and checked in CI.
- A website with the documentation, a page for every option of every tool, and a playground that runs the real gnux, compiled to WebAssembly, on an in-memory filesystem.
- Release archives for Linux and macOS (amd64, arm64) and Windows (amd64), with a checksums file.

### Changed

- The project is now gnux, a portable implementation of the GNU core utilities. `rmx`, which it started as, was rewritten as one of its tools, with GNU's full `rm` flag surface.
