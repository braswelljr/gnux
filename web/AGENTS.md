# gnux website

This file provides guidance to coding agents working in `web/`. The Go project has its own
[`AGENTS.md`](../AGENTS.md) at the repository root; this one covers only the website.

A landing page, the documentation, and an in-browser playground for gnux. It is a single
Next.js App Router application with no backend: the documentation is MDX generated by the Go
project, and the playground runs gnux itself, compiled to WebAssembly, in the visitor's tab.

## Tech stack

| Layer        | Technology                                                       |
| ------------ | ---------------------------------------------------------------- |
| Framework    | Next.js 16 (App Router, Turbopack)                               |
| Language     | TypeScript 5.9, React 19                                         |
| Styling      | Tailwind CSS v4 via `@tailwindcss/postcss`                       |
| Docs         | Fumadocs (`fumadocs-ui`, `fumadocs-core`, `fumadocs-mdx`), Shiki |
| URL state    | nuqs                                                             |
| Motion       | `motion/react`, on the landing page only                         |
| Icons        | `lucide-react`, and only it                                      |
| Tests        | `node --test` running TypeScript directly, in `test/`            |
| Package man. | pnpm, pinned via `packageManager`                                |

TypeScript is pinned to `^5.9.3` on purpose. TypeScript 7 ships the Go compiler and no longer
exposes the JavaScript compiler API that typescript-eslint requires. Do not raise it.

## Repository layout

```text
content/docs/        GENERATED by `pnpm docs:gen`; vX.Y/ downloaded from the releases. Not committed. Never edit by hand.
public/              gnux.wasm and wasm_exec.js, GENERATED by `pnpm wasm`.
lib/                 Framework-agnostic helpers (cn, guards, docs source)
  playground/        The in-memory filesystem and the wasm loader. No React, no DOM.
scripts/             gen.mjs (runs before dev and build), check-seo.mjs
source.config.ts     Fumadocs MDX collections
src/
  app/               Routes. (home) is the landing page and the playground.
  components/
    ui/              Atoms and molecules, exported from index.ts
    home/            Landing page organisms
    playground/      Playground organisms
    shared/          Organisms used across pages
  config/            site.ts (the one SiteConfig), navigation, playground examples
  hooks/             Reusable React hooks
  providers/         The provider tree (base.tsx)
  styles/main.css    The Tailwind entry: theme and base styles
  utils/             App-specific helpers (createMetadata)
test/                Test suites and the wasm harness
```

Import aliases: `@/*` is `src/*`, `lib/*` is `lib/*`, `@content-source/*` is the generated
`.source/*`. Files under `lib/playground/` and `test/` import each other with the `.ts`
extension, because Node runs them without a bundler.

## Things that are easy to get wrong here

- **`content/docs/` and `public/gnux.wasm` are build inputs from the Go project.** Change the
  Go source and run `pnpm gen`. `scripts/gen.mjs` does this before `dev` and `build`; on a host
  without Go (Vercel) it downloads the release `../go.mod` names, checksum-verified, into
  `node_modules/.cache/gnux`. `gnux.wasm` is never committed, so a deploy always builds it from
  the deployed commit.
- **Never hardcode the tool list.** The playground reads it from the running build
  (`session.tools`), and filters its examples against it.
- **`lib/playground/memfs.ts` implements a contract owned by Go** (`$GOROOT/src/syscall/fs_js.go`).
  An error must carry a `code` Go knows, or Go panics. `pnpm test` runs the real wasm against
  it: change the filesystem and that suite is the judge.
- **`lib/playground/` stays plain erasable TypeScript**: no enums, no parameter properties, no
  path aliases. Node strips the types and runs what is left.
- **The site URL is `siteConfig.url`**, from `NEXT_PUBLIC_SITE_URL`. Never write the origin
  into a component.

## Rules

The rules are written out in [`../docs/rules/`](../docs/rules/). The ones that apply to `web/`:

- [No em dashes](../docs/rules/no-em-dashes.md), anywhere we write: copy, comments, metadata,
  accessible names. Use the punctuation that names the relationship.
- [A public page describes itself](../docs/rules/a-public-page-describes-itself.md): every
  page builds its metadata with `createMetadata(siteConfig, {...})`. No `Metadata` literals.
- [The markup says what the thing is](../docs/rules/the-markup-says-what-the-thing-is.md):
  semantic elements and landmarks before ARIA, one `h1` per page, no skipped levels.
  `Heading` takes `level` and `size` separately.
- [Build the UI from atoms upward](../docs/rules/build-the-ui-from-atoms-upward.md): check
  `src/components/ui` first. Pages compose organisms; they do not style from scratch.
- [A dark step mirrors its light one](../docs/rules/a-dark-step-mirrors-its-light-one.md):
  `text-red-700 dark:text-red-300`. Fumadocs' `fd-*` tokens already switch with the theme and
  are the default choice, so the site matches the docs.
- [Type sizes come from the scale](../docs/rules/type-sizes-come-from-the-scale.md):
  `text-xs` through `text-3xl`, never `text-[13px]`. The one exception is `Heading`'s
  `display` size (scale steps `text-4xl` to `text-6xl`), for a page's single hero headline.
- [An icon-only button takes an icon size](../docs/rules/an-icon-only-button-takes-an-icon-size.md):
  `size="icon"` or `"icon-sm"`, an `aria-label`, and the icon `aria-hidden`.
- [Icons come from the installed set](../docs/rules/icons-come-from-the-four-installed-sets.md):
  here that is `lucide-react` alone.
- [State a reader can arrive at lives in the URL](../docs/rules/state-a-reader-can-arrive-at-lives-in-the-url.md):
  through `nuqs`. The playground's `?cmd=` is the example.
- [Data from outside is unknown until checked](../docs/rules/data-from-outside-is-unknown-until-checked.md):
  the wasm API and URL parameters are narrowed with the guards in `lib/guards.ts`, never cast.
- [An array fallback is a type check](../docs/rules/an-array-fallback-is-a-type-check-never.md):
  `Array.isArray(v) ? v : []`, never `v ?? []`.
- [The shortest path, and only one of them](../docs/rules/the-shortest-path-and-only-one-of-them.md):
  one primary action per view, labels that say what will happen, a reason beside anything
  disabled, and no meaning carried by color alone.
- [Copying goes through `useCopyToClipboard`](../docs/rules/copying-goes-through-usecopytoclipboard.md):
  never `navigator.clipboard` in a component.

`test/rules.test.ts` enforces the ones a pattern can check: em dashes, array fallbacks,
arbitrary type sizes, clipboard access, icon imports and `createMetadata`.

Motion is decorative and never carries meaning:

- `motion/react` is used by `Reveal` alone, on the landing page: opacity and transform, short,
  once.
- The typing demos (`TypingTerminal`, `TypingCode`, the hero's `Keyboard`) and the ambient
  `AnimatedBackground` are plain React state and CSS keyframes, so they also appear on the 404
  page and behind the playground. Each one is `aria-hidden` with a text alternative beside it,
  runs only while on screen (`useInView`), and under `prefers-reduced-motion` shows its finished
  state and holds still (`useReducedMotion` from `src/hooks`, never motion's, so hydration
  matches the server).
- Nothing animates inside the docs or inside the playground's live terminal; the docs carry the
  look through static styling in `src/styles/fumadocs.css`.

The visual language lives in `src/styles/main.css`: the three signal hues (`--signal-1..3`,
darker steps in the light theme), and the utilities `text-signal`, `border-signal`,
`glow-signal` and `aurora-glow-*`. Use them rather than writing a new gradient.

Use US spelling.

## Definition of done

A change is done when all of these exit 0, in `web/`:

```bash
pnpm lint
pnpm typecheck
pnpm format:check
pnpm test
pnpm build
```

After a change to metadata, routes or the docs source, also run `pnpm test:seo`.
